# xetead-bot

TRPG 캠페인의 전투를 자동 정산하는 Mastodon 봇.

---

## 실행

### 환경 변수

`.env` 파일을 생성하거나 환경 변수를 직접 설정한다.

| 변수                               | 설명                                      |
|----------------------------------|-----------------------------------------|
| `ADMIN_MASTODON_ID`              | Admin 마스토돈 계정 (`user` 또는 `user@domain`) |
| `MASTODON_ACCESS_TOKEN`          | 봇 계정 액세스 토큰                             |
| `MASTODON_API_BASE_URL`          | 마스토돈 인스턴스 URL                           |
| `GOOGLE_SPREADSHEET_CREDENTIALS` | Google 서비스 계정 JSON (문자열)                |
| `DB_SPREADSHEET_KEY`             | 스프레드시트 ID (내부용 자동화 DB)                  |
| `FIELD_SPREADSHEET_KEY`          | 스프레드시트 ID (관중 공개용 실시간 전투 UI "필드" 시트)     |
| `FIELD_LOG_SHEET_NAME`           | (선택) `DB_SPREADSHEET_KEY` 내 크래시 복구용 "필드" 워크시트 이름. 기본값 `필드`. 여러 배포(예: 운영/테스트)가 같은 `DB_SPREADSHEET_KEY`를 공유하면 반드시 배포별로 다른 값을 지정해야 한다 — 아니면 서로의 진행 중 전투 행을 upsert로 덮어쓴다 |

### 봇 시작

의존성은 [uv](https://docs.astral.sh/uv/)로 관리한다 (`pyproject.toml` / `uv.lock`).

```bash
uv sync
PYTHONPATH=app uv run python app/bot/main.py
```

## 스프레드시트 설정

전투 로직이 참조하는 "버프"/"버프_패시브"/"스킬_캐릭터"/"스킬_에너미"/
"스킬_패시브" 시트의 컬럼 스키마와, 그 컬럼에 넣는 클래스 이름·enum 값
목록은 [SPREADSHEET_SCHEMA.md](SPREADSHEET_SCHEMA.md)에 정리했다.

### 캐릭터 시트

| 컬럼                                                                               | 설명                                |
|----------------------------------------------------------------------------------|-----------------------------------|
| `name`                                                                           | 캐릭터 이름                            |
| `mastodon_id`                                                                    | 마스토돈 계정 (`user` 또는 `user@domain`) |
| `curr_hp`, `max_hp`                                                              | 현재/최대 체력                          |
| `atk`                                                                            | 공격력                               |
| `attack_range`                                                                   | 사거리                               |
| `m_res`                                                                          | 마법 저항 (`낮음` / `보통` / `높음`)        |
| `is_magic`                                                                       | 마법 공격자 여부                         |
| `max_cost`                                                                       | 최대 코스트                            |
| `passive_buff_id`                                                                | 패시브 버프 ID                         |
| `skill_1_id` ~ `skill_N_id`                                                      | 스킬 ID 목록                          |
| `stat_physical`, `stat_knowledge`, `stat_human`, `stat_magic`, `stat_technology` | 비전투 스탯 (0–5) — 육체·지식·인간·마법·기술     |
| `gold`                                                                           | 보유 골드                             |
| `daily_quest_date`                                                               | 마지막 일일 의뢰 날짜 (`YYYY-MM-DD`)       |
| `daily_quest_status_id` (선택)                                                     | `[의뢰]` 판정 대기 중인 봇 게시물 ID. 진행 중이 아니면 빈 칸. 봇 재기동 시 이 컬럼으로 진행 상태를 복원한다(컬럼 자체가 없으면 재기동 복원 없이 기존처럼 동작) |

### 에너미 시트

전투 전용 캐릭터(몬스터 등) 데이터. 컬럼 구성은 캐릭터 시트와 같되 비전투 스탯·`gold`·`daily_quest_date` 컬럼은 없으며, 스킬은 `스킬_캐릭터`가 아닌 `스킬_에너미` 시트에 등록한다.

| 컬럼                           | 설명                                                    |
|------------------------------|-------------------------------------------------------|
| `name`                       | 에너미 이름                                                |
| `mastodon_id`                | 마스토돈 계정. 비워두면 계정 없는 에너미(`[배치/...]`로만 조작, 프록시 커맨드 필요) |
| `curr_hp`, `max_hp`          | 현재/최대 체력                                              |
| `atk`                        | 공격력                                                   |
| `attack_range`               | 사거리                                                   |
| `m_res`                      | 마법 저항 (`낮음` / `보통` / `높음`)                            |
| `is_magic`                   | 마법 공격자 여부                                             |
| `max_cost`                   | 최대 코스트                                                |
| `passive_skill_id`           | 패시브 스킬 ID                                             |
| `skill_1_id` ~ `skill_N_id`  | 스킬 ID 목록 (`스킬_에너미` 시트의 `id` 참조)                       |

- `에너미` 시트 자체가 없어도(레거시 데이터) 봇은 경고만 남기고 에너미 없이 정상 동작한다.
- `mastodon_id`가 있는 에너미는 캐릭터와 동일하게 본인 계정으로 전투 커맨드를 입력할 수 있다.
- 판정/의뢰/아이템 사용 등 비전투 커맨드의 대상이 될 수 없다.

### 아이템 시트

독립적인 코스트와 사거리를 가진 소비형 슬롯. 효과·대상 규칙은 스킬 시스템을 그대로 재사용하며, 효과는 **1개**(`effect_0`)만 가진다.

| 컬럼                                                                | 설명                                                                                    |
|-------------------------------------------------------------------|---------------------------------------------------------------------------------------|
| `id`                                                              | 아이템 이름 (= ID, 고유)                                                                     |
| `target_rule`                                                     | 대상 규칙 클래스명 ([스킬 대상 규칙](#스킬-대상-규칙) 참조)                                              |
| `cost`                                                            | 코스트                                                                                   |
| `range`                                                           | 사거리 (아이템 고유 — 캐릭터 사거리와 무관)                                                            |
| `effect_0` (및 부속 컬럼)                                            | 효과 1개, [SPREADSHEET_SCHEMA.md](SPREADSHEET_SCHEMA.md#effect_n-컬럼-패턴-스킬아이템-공용)의 `effect_N` 컬럼 패턴과 동일 |
| `item_type`                                                       | 아이템 종류 (드롭다운). 값 목록과 각 종류의 사용 가능 맥락은 아래 참조                                          |

`item_type` 값:

| 값          | 사용 가능 맥락                | 설명                                                                                          |
|------------|--------------------------|-----------------------------------------------------------------------------------------------|
| `소모품`      | 전투 + 비전투 모두              | 전투용 스테이터스와 효과를 가지되 비전투 상황에서도 `[아이템명]`으로 사용 가능. 비전투 사용 시 코스트/사거리는 무시된다. 사용하면 소모(개수 차감)된다 |
| `전투 소모품`   | 전투만                     | 독립적인 코스트/사거리를 가진 소비형 스킬 슬롯. 기존 아이템 구현과 동일. 사용하면 소모된다                                      |
| `비전투 소모품`  | 비전투만                    | `effect_0`은 항상 비워 둔다. 자신을 대상으로만 사용 가능하며, 전투 중 사용하려 하면 오류가 난다. 효과는 아이템별 전용 로직으로 처리(현재 "수상한 물약"만 구현, [사용법](#사용아이템명대상개수) 참조) |
| `부적`       | (미구현)                   | 전투 시 특수 효과를 내는 추가 패시브 스킬. 현재 구현되지 않음                                                        |
| `기타`       | 없음                      | 소지 자체가 목적인 아이템(스토리 진행용 등). 전투/비전투 어느 쪽으로도 사용할 수 없다                                        |

- `target_count` 컬럼은 없다. 대상 수 상한 검증 없이 `target_rule`에 위임한다.
- `기타`/`부적`/`비전투 소모품`은 대상 규칙·코스트·사거리 슬롯이 의미가
  없으므로 `target_rule`/`cost`/`range`를 비워 둘 수 있다(빈 값은 각각
  `""`/`0`/`0`으로 취급). 그 외 `item_type`(`소모품`/`전투 소모품`)은
  기존과 동일하게 세 컬럼이 필수다.
- 커맨드 형식은 [아이템](#아이템) 참조.

### 인벤토리 시트

캐릭터별 아이템 보유 현황. `(character_name, item_id)`가 key인 dict처럼 취급한다.

| 컬럼               | 설명     |
|------------------|--------|
| `character_name` | 캐릭터 이름 |
| `item_id`        | 아이템 이름 |
| `count`          | 보유 개수  |

- 아이템 사용이 확정되면 `count`가 **즉시 1 차감되어 시트에 기록**된다.
- 보유 개수가 0이거나 인벤토리에 없는 아이템은 사용할 수 없다.
- **대련·상시전투에서는 아이템을 사용할 수 없다.**

### 수상한 효과 시트

`item_type`이 `비전투 소모품`인 "수상한 물약" 전용 텍스트 풀. `[수상한 물약]`
시 이 중 하나가 무작위로 출력된다.

| 컬럼       | 설명                                                                              |
|----------|---------------------------------------------------------------------------------|
| `effect` | 출력될 효과 텍스트 1개. `체력이 {N} 회복된다.` 형태로 쓰면 봇이 그 캐릭터의 `curr_hp`를 자동으로 반영한다(그 외 텍스트는 출력만 하고 별도 처리 없음) |

같은 컬럼에 행을 추가하는 것만으로 효과 풀을 늘릴 수 있다.

### 일일 의뢰 시트

`id`나 행 단위 검증이 없다. `client_category`/`client_name`/`quest_content`
세 컬럼 쌍(`xxx`, `xxx_active`)은 사실상 독립된 3개의 값 풀을 한 워크시트에
모아둔 것으로, 같은 행에 있어도 서로 대응하지 않는다. `[의뢰]` 요청이 오면
각 풀에서 `xxx_active`가 `TRUE`인 값 중 하나를 무작위로 뽑아 조립한다. 일반
의뢰 시트와는 무관하게 항상 동작한다(위치/상시조사 활성 여부를 보지 않는다).

| 컬럼                       | 설명                                                                                      |
|--------------------------|-------------------------------------------------------------------------------------------|
| `client_category`        | 의뢰인 분류 (예: `장터`, `마을`, `길 잃은`)                                                        |
| `client_category_active` | 이 `client_category` 값을 뽑기 대상에 포함할지 (`TRUE`/`FALSE`)                                    |
| `client_name`             | 의뢰인 이름. **조사(로부터/으로부터)까지 포함해서 입력** (봇은 조사를 판별하지 않고 그대로 이어붙인다. 예: `노인으로부터`, `어린아이로부터`) |
| `client_name_active`      | 이 `client_name` 값을 뽑기 대상에 포함할지 (`TRUE`/`FALSE`)                                        |
| `quest_content`           | 봇이 그대로 출력할 의뢰 내용                                                                       |
| `quest_content_active`    | 이 `quest_content` 값을 뽑기 대상에 포함할지 (`TRUE`/`FALSE`)                                      |

세 풀 중 하나라도 active인 값이 하나도 없으면 의뢰를 제공하지 않는다.
`{client_category} {client_name} {quest_content} 의뢰를 맡겼다`로 이어붙여
출력한다.

### 일일 의뢰 결과 메시지 시트

| 컬럼             | 설명                                                          |
|----------------|-------------------------------------------------------------|
| `success_type` | 성공 유형: `대성공` (합계 ≥ 7) / `성공` (합계 ≥ 5) / `아슬아슬한 성공` (합계 < 5) |
| `message`      | 해당 유형에서 랜덤으로 선택될 메시지 텍스트 (`success_type`은 붙이지 않는다 — 봇이 항상 `{success_type}! ` 접두어를 붙여 출력) |

같은 `success_type`의 행이 여러 개 있으면 그 중 하나가 무작위로 선택된다. 해당 유형의 행이 없으면 메시지 없이 `success_type!`만 출력된다.

### 일반 의뢰 시트

상시조사(`[상시조사]`)에서 사용하는 시트. 행 하나가 **장소 행** 또는
**의뢰 행** 둘 중 하나이며, `name`이 비어 있으면 장소 행, 채워져 있으면
의뢰 행이다.

| 컬럼                | 설명                                                                 |
|-------------------|--------------------------------------------------------------------|
| `id`              | 장소 행: 장소 이름 자체 (예: `아도스`). 의뢰 행: `{장소 이름}_{type}` (예: `아도스_운반`) |
| `active`          | 장소 행에서만 사용 — 이 장소가 현재 활성(현재 위치)인지 (`TRUE`/`FALSE`, 정확히 한 장소만 `TRUE`) |
| `location`        | 의뢰 행에서만 사용 — 의뢰 수주처 이름 (상시조사 메뉴/카드에 표시됨, 예: `광장`)                |
| `name`            | 의뢰 이름 (장소 행은 비워 둔다)                                              |
| `description`     | 장소 행: `[상시조사]` 시 메뉴 위에 출력할 장소 소개(선택지 안내 문구까지 포함해서 작성). 의뢰 행: 장소 선택 시 출력할 의뢰 상황 묘사 |
| `type`            | 의뢰 행: 계열 `운반` / `탐사` / `전투` (한 장소당 세 계열 모두 한 행씩 필요)              |
| `subtype`         | 의뢰 행: 종류 `상시` / `일반`                                              |
| `reward`          | 의뢰 행: 보상 내용 (텍스트, 의뢰 종료 시 수동 정산)                                  |
| `available_until` | 의뢰 행: 클리어 가능 기간 (텍스트, 그대로 출력)                                     |
| `taken_by`        | 의뢰 행: 이 의뢰를 수주한 캐릭터 acct들을 쉼표로 이어붙인 값 (`[수락]` 시 봇이 기록). 비어 있으면 미수주 |

장소 행 하나(`active=TRUE`)와 그 장소의 `id`를 접두사로 갖는 의뢰 행
3개(운반/탐사/전투)가 한 블록을 이룬다. 다음 장소로 넘어가려면 이전 장소의
`active`를 `FALSE`로, 새 장소의 `active`를 `TRUE`로 바꾼다.

## 전투 시스템

### 전장 구조

전장은 **7열 × 진영(아군/적군)** 구조다. 각 열에는 최대 3명이 위치할 수 있다.

```
적군  [1열] [2열] [3열] [4열] [5열] [6열] [7열]
아군  [1열] [2열] [3열] [4열] [5열] [6열] [7열]
```

사거리는 열 번호 차이로 계산한다.

```
사거리 = |내 열 - 대상 열|

예) 내가 2열, 사거리 2 → 1열~4열의 적 공격 가능
```

### 캐릭터 스탯

| 스탯    | 설명                                           |
|-------|----------------------------------------------|
| 공격력   | 기본 공격 및 공격 계수 스킬의 주사위 상한                     |
| 체력    | 최대/현재 HP                                     |
| 사거리   | 공격 가능한 열 거리 (1 = 인접, 3 = 원거리)                |
| 공격 속성 | 물리 / 마법                                      |
| 마법 저항 | 낮음(+15%) / 보통(±0) / 높음(−15%). 마법 공격을 받을 때 적용 |
| 코스트   | 턴당 행동 자원                                     |

### 라운드 페이즈

한 라운드는 4단계로 진행된다.

```
① 적군 행동 선언
   봇이 "[라운드 N] 적군 행동 선언" 게시물을 올린다.
   이 시점에 적군의 이동이 처리된다.
   적군 플레이어가 있다면 이 게시물에 답글로 커맨드를 입력한다.

② 아군 행동  ← 플레이어 행동 타이밍
   봇이 "[라운드 N] 아군 행동" 게시물을 올린다.
   이 게시물에 답글로 커맨드를 입력하면 된다.
   모두 입력을 마치면 관리자에게 알린다.

③ 적군 행동 정산
   ①에서 선언된 적군의 공격·스킬 효과가 실제로 처리된다.
   ②에서 건 버프(도발 등)가 이 시점에 반영된다.
   HP 변동 결과가 출력된다.

④ 라운드 종료
   버프/디버프 지속 턴이 차감된다.
   [전투 속행] 또는 [전투 종료]로 전투를 이어간다.
```

## 커맨드 입력

### 커맨드 형식

커맨드는 `[행동1 - 행동2 - ...]` 형태로 작성하며, `-`로 복수 행동을 연결한다.

```
예) [이동/3 - 공격/오크A]
    [이동/3 - 강타/오크A]
    [공격/골렘 - 공격/오크A]
    [도발 - 방어태세]
```

**Discord 봇 예시**: `/행동 이름:테스트 커맨드:"[이동/2 - 공격/에너미]"`

### 행동 종류

#### 이동

```
이동/[열 번호]
예) 이동/3   → 3열로 이동
```

- 목표 열에 빈 슬롯이 있어야 한다 (열당 최대 3명).
- 코스트 소모 없음.

#### 기본 공격

```
공격/[대상 이름]
예) 공격/오크A
```

- 대상이 사거리 내에 있어야 한다.
- 코스트 1 소모.
- 진영 제한이 없다 — 아군을 대상으로 지정해도 그대로 대미지가 들어간다.

#### 스킬 / 아이템

스킬과 아이템은 별도 키워드("스킬/" 등) 없이 이름으로 바로 시작한다 —
시전자가 보유한 스킬 목록에서 먼저 찾고, 없으면 인벤토리의 아이템에서
찾는다(둘 다 없으면 오류).

```
[스킬명]                   # 자신 고정 (대상 생략)
[스킬명]/[대상1]/[대상2]   # 이름 지정
[스킬명]/[열 번호]         # 열 지정 (광역)
[아이템명]/[대상](/[개수]) # 아이템 사용
```

```
예) 강타/오크A          ← 이름 지정
    광역폭발/2/3         ← 열 번호 지정
    자가회복             ← 자신 고정 (대상 생략)
    포션/오크A           ← 전투 중 아이템 사용
```

[비전투 명령어](#비전투-명령어)의 `[아이템명(/대상)(/개수)]`도 이 문법을
그대로 따른다 — 전투 중이든 밖이든 아이템명으로 바로 시작한다는 점은
동일하며, 대상/개수 해석 규칙(`handle_use_item`)만 맥락에 따라 다르다.

대상 지정 방식은 스킬마다 다르다.

| 방식    | 입력 형식    | 사거리 제한 |
|-------|----------|--------|
| 이름 지정 | 캐릭터 이름   | 있음     |
| 열 지정  | 1~7 열 번호 | 없음     |
| 자신 고정 | 생략       | 없음     |

### 코스트 시스템

- 각 캐릭터는 라운드마다 정해진 코스트를 보유한다.
- 행동별 기본 소모량: 이동 **0** / 공격 **1** / 스킬·아이템 **스킬마다 다름**
- 커맨드 전체의 코스트 합산이 보유 코스트를 초과하면 **커맨드 전체가 취소**된다 (일부만 처리되지 않음).
- 라운드 시작 시 코스트가 전액 회복된다.

### 검증 항목

커맨드 실행 전 아래 항목을 순서대로 검증하며, 하나라도 실패하면 전체 커맨드가 취소된다.

1. 커맨드 사용자가 전장에 존재하는지
2. 지정한 스킬이 캐릭터에 등록되어 있는지
3. 스킬 대상 수가 `target_count`를 초과하지 않는지
4. 커맨드 전체 코스트가 잔여 코스트 이내인지
5. 공격/힐 대상이 전장에 존재하는지, 사거리 내인지
6. 이동 목적지에 자리가 남아있는지

### 캐릭터 이름 규칙

커맨드에 캐릭터 이름을 입력할 때는 다음 문자만 허용된다.

- 한글 (완성형 음절, 자모)
- 영문 (A–Z, a–z)
- 숫자 (0–9)
- 공백
- 언더스코어(`_`), `!`, `^`, `~`

```
가능: 오크A, Monster1, 아군 기사, 스킬_1!, 스킬^^, 스킬~1
불가: 오크-A, 몬스터@1
```

## 대미지 · 회복 계산

```
최종 수치 = floor(기본값 × (1 + Σ배율 보정)) + Σ정수 보정
```

### 대미지 기본값 종류

| 종류         | 설명                          |
|------------|-----------------------------|
| 고정값        | 정해진 수치                      |
| 공격 굴림      | `nd6(마일스톤N, 공격력)` 주사위 굴림 결과 |
| 기본 공격력     | 캐릭터의 공격력 스탯                 |
| 현재 체력 (자신) | 시전 시점의 자신 HP                |
| 현재 체력 (대상) | 시전 시점의 대상 HP                |
| 이전 효과의 대미지 | 같은 스킬의 앞선 효과가 입힌 대미지        |

### 마법 공격

마법 공격은 대상의 마법 저항에 영향을 받는다. 물리 공격은 영향 없음.

| 마법 저항       | 효과       |
|-------------|----------|
| 낮음 (WEAK)   | 대미지 +15% |
| 보통 (NORMAL) | 변화 없음    |
| 높음 (STRONG) | 대미지 -15% |

### 회복

회복량도 대미지와 같은 공식으로 계산된다. 최대 체력을 초과해 회복할 수 없다.

## 버프 · 디버프 시스템

### 지속 시간

| 종류    | 해제 조건                          |
|-------|--------------------------------|
| 턴 지속  | 라운드 종료 시마다 1 차감. 0이 되면 해제.     |
| 횟수 지속 | 공격하거나 피격당할 때마다 1 차감. 0이 되면 해제. |
| 영구    | 별도 해제 수단이 없으면 계속 유지.           |

### 발동 타이밍

| 타이밍                        | 발동 시점                          |
|-----------------------------|---------------------------------|
| `ON_BATTLE_START`            | 전투 시작 시                        |
| `ON_ROUND_START`             | 라운드 시작 시                       |
| `ON_ACTION`                  | 자신이 공격 또는 피격 시                 |
| `ON_ENEMY_POST_ACTION`       | 적 후행(정산) 시                     |
| `ON_ROUND_END`               | 라운드 종료 시                       |
| `ON_ENEMY_MOVE`              | 적이 이동할 때 (자발적/강제 이동 모두)        |
| `ALLY_DAMAGED`               | 같은 열의 아군(자신 포함)이 피격 시          |
| `ALLY_IN_RANGE_DAMAGED`      | 사거리 내 아군(자신 포함)이 피격 시          |
| `ALLY_IN_RANGE_ATTACKED`     | 사거리 내 아군(자신 포함)이 누군가를 공격할 때    |

패시브 스킬("스킬_패시브" 시트)의 `트리거` 컬럼도 이와 유사한 값을 쓰지만
완전히 같은 목록은 아니다 — 예를 들어 `사거리 내 아군 공격 시`는 아직 패시브
스킬 트리거로는 제공되지 않는다.

### 구현된 버프 목록

버프 클래스 이름은 "버프" 시트의 `buff_class_name` 컬럼에 그대로 입력한다.

| 버프 클래스                                | 효과                                          |
|-----------------------------------------|---------------------------------------------|
| `BuffAtk`                                | 공격력 수치 증가/감소                                 |
| `BuffGivenDamage`                        | 주는 대미지 배율 변경                                 |
| `BuffReceivedDamage`                      | 받는 대미지 배율 변경                                 |
| `BuffReceivedDamageMark`                  | `BuffReceivedDamage`와 동작 동일, 별도 클래스(같은 부여자가 같은 대상에게 `BuffReceivedDamage` 기반 디버프를 동시에 걸 때 식별 충돌 방지용) |
| `BuffGivenAndReceivedDamage`              | 주는 대미지와 받는 대미지를 함께 변경 (트레이드오프)                |
| `BuffGivenDamageAgainstDebuff`            | 디버프가 걸린 대상을 공격하면 주는 대미지 증가                    |
| `BuffGivenHeal`                           | 주는 회복량 배율 변경                                 |
| `BuffDamageOverTime`                      | 매 라운드 종료 시 고정 대미지                            |
| `BuffDamageOverTimePerReferencedBuffStack`| 매 라운드 종료 시 다른 버프의 스택 수에 비례한 고정 대미지            |
| `BuffHealOverTime`                        | 매 라운드 종료 시 고정 회복                             |
| `BuffNoDamage`                            | 대미지 1회 무효 (방어막류)                            |
| `BuffNoHeal`                              | 회복 1회 무효                                    |
| `BuffTaunt`                               | 도발 — 홀더의 모든 공격이 도발자를 향함                      |
| `BuffReflect`                             | 반사 — 받은 대미지를 공격자에게 되돌림                        |
| `BuffSacrifice`                           | 희생 방어 — 보호 대상이 받을 공격을 대신 맞음                   |
| `BuffFormation`                           | 진형 밀집 시 받는 대미지 감소                            |
| `BuffFracture`                            | [균열] 적층형 순수 마커 디버프 (다른 효과가 스택을 조회해 활용)        |
| `BuffCatastrophe`                         | [재앙] 적층형 순수 마커 — 전투 종료 시 스택×3만큼 자신의 체력 소모     |
| `BuffStackingMark`                        | 범용 적층형 순수 마커 (재앙/균열과 동일 목적, 별도 식별가 필요할 때)     |
| `BuffConditionalDamage`                   | 적 후행 시 조건이 만족되면 고정 대미지 부여 (Condition 조합 필수) |

| `BuffCounterDamageOnMarkedAllyAttack`     | 사거리 내에서 특정 버프를 보유한 아군이 공격하면 같은 대상에게 추가 대미지  |
| `BuffCounterDamageOnEnemyMove`            | 사거리 내 적이 이동할 때마다 반격 대미지 (대상 디버프 스택에 비례)     |
| `BuffHealAndBuffStackOnDealingDamage`     | 대미지를 줄 때마다 그 대미지의 %만큼 자가 회복 + 조건 충족 시 참조 버프 1스택 부여 (버프_패시브 전용) |
| `BuffReduceCostNextRound`                 | 다음 라운드 시작 시 1회, 코스트를 지정한 만큼 감소             |
| `BuffIgnite`                              | 부여 시점 대상의 열을 저장해두는 디버프. 지속시간이 끝나는 라운드 종료 시점에 대상이 그 열에 그대로 있으면 부여자 공격 굴림 150% 대미지. 서로 다른 열로 부여되면 동시에 여러 개 유지 가능(재부여 판정에 열 값도 반영) |

### 도발 상세

- 도발이 걸린 캐릭터는 적군이 공격 대상을 정할 때 강제로 그 캐릭터로 대상이 교체된다.
- **아군 행동(②)** 페이즈에서 도발을 걸면, 같은 라운드 **적군 행동 정산(③)** 때 바로 효과가 적용된다.
- 도발 대상이 사거리 밖에 있으면 공격이 실행되지 않는다.

## 봇 커맨드

### 기본 규칙

- 봇은 **멘션(@시스템계정)** 에만 반응한다.
- Admin 계정(`ADMIN_MASTODON_ID`)의 멘션은 전투 관리 커맨드로 처리된다.
- 일반 캐릭터는 **답글의 맥락**(어느 게시물에 답글을 달았는지)에 따라 전투 커맨드 또는 비전투 커맨드로 처리된다.
- 최대 게시물 길이는 500자이며, 초과 시 잘린다.
- 봇 답글의 가시성: 원본 멘션의 가시성을 그대로 유지.

### 공개 필드 시트

관중에게 공개하는 실시간 전투 UI. 내부 자동화 DB(`DB_SPREADSHEET_KEY`)와는
별개인 `FIELD_SPREADSHEET_KEY` 스프레드시트의 "필드" 시트에 라운드/페이즈/
캐릭터 상태/버프/적 선언 내용을 갱신하고, 그 시트를 그대로 이미지로 캡처해
Mastodon 게시물에 첨부한다.

- 이미지가 첨부되는 시점: 라운드 시작(`[전투개시]`/`[전투속행]`), 라운드
  종료(버프 턴 차감/제거가 끝난 직후), 그리고 본 전투 캐릭터 커맨드/프록시
  커맨드의 답글.
- 대련·상시전투에는 적용되지 않는다.
- 시트 캡처나 업로드가 실패해도 전투 진행 자체는 막히지 않고 텍스트만
  게시된다.

### Admin 명령어

Admin 계정의 멘션은 답글 여부에 무관하게 항상 Admin 커맨드로 처리된다.

#### `[전투 준비]`

새 전투 세션을 생성한다.

- 실행 시점에 스프레드시트 캐릭터 시트를 새로 읽어 최신 데이터를 반영한다.
- 봇 답글 자체가 **참전 신청 스레드**가 된다.
- 이 게시물에 답글을 달면 해당 캐릭터가 참전 신청자 목록에 추가된다.

```
[전투 준비]
```

#### `[배치/캐릭터이름/팩션 열]`

전투 시작 전 특정 캐릭터를 수동으로 지정 열에 배치한다.

```
[배치/늑대/적군 3열]
[배치/용병A/아군 2]
```

- 팩션: `아군` 또는 `적군`
- 열: `1`~`7` 또는 `1열`~`7열`

#### `[전투 개시]`

참전 신청자 및 수동 배치 목록을 확정하고 전투를 시작한다.

- 아군 참전 신청자는 열(1~7)에 자동 배치(랜덤 분산)된다.
- 참전 신청자 중 체력이 0인(전투불능) 캐릭터는 자동 배치에서 제외되고
  누구인지 오류로 보고된다 — 캐릭터 시트를 고쳐 다시 [전투 준비]부터
  진행해야 한다.
- 첫 페이즈(적군 행동 선언)의 게시물이 퍼블릭으로 게시되며, 공개 필드 시트
  이미지(아래 [공개 필드 시트](#공개-필드-시트) 참고)가 함께 첨부된다.
- `[전투개시]「전투 이름」`처럼 대괄호 뒤에 「」로 감싸 전투 이름을 지정하면
  공개 필드 시트의 타이틀에 반영된다. 「」를 대괄호 안에 넣으면(예:
  `[전투개시「이름」]`) `[전투개시]` 커맨드 자체가 인식되지 않으니 주의.
  지정하지 않으면 기존 표기가 유지된다.

```
[전투개시]
[전투개시]「1라운드 습격전」
```

#### `[진행]`

현재 페이즈에서 다음 페이즈로 진행한다.

| 페이즈       | 설명                | 커맨드 수신 |
|-----------|-------------------|--------|
| 적군 행동 선언  | 적군 캐릭터가 커맨드를 입력한다 | ✅      |
| 아군 행동     | 아군 캐릭터가 커맨드를 입력한다 | ✅      |
| 적군 공격 정산  | 적군의 선언된 행동이 처리된다  | ❌      |
| 라운드 종료 대기 | 버프 갱신 후 대기        | ❌      |

- "라운드 종료 대기"로 진행하는 시점(버프 턴 차감/제거까지 끝난 직후)의
  공개 게시물에는 공개 필드 시트 이미지가 함께 첨부된다.
- 이 시점에 **체력이 0 이하인 캐릭터는 필드에서 자동으로 제거**되고,
  게시물에 "【탈락】\n이름 | 탈락" 목록으로 표시된다. 동료(소환수)를 보유한
  캐릭터가 탈락하면 동료도 함께 제거된다(동료 혼자 체력이 0이 되는 것은
  소환자의 탈락과 무관하다 — 재소환될 수 있다).

#### `[전투 속행]`

라운드 종료 대기 상태에서 다음 라운드(적군 행동 선언)로 진행한다. 이때도
공개 게시물에 공개 필드 시트 이미지가 첨부된다.

#### `[전투 종료]`

세션을 종료하고 모든 전투 상태를 초기화한다. 최종 체력 목록과 전투 종료
시점 효과(유예된 [재앙] 등)의 정산 결과를 답글로 보여준다 — 다른 정산
게시물과 달리 계산식도 CW로 접지 않고 본문에 그대로 포함해 한 번에 확인할
수 있다.

#### `[상시전투]`

상시조사 구간 중 발생하는 전투를 준비한다.

- 멘션된 아군 계정들이 참여 대상이 된다.
- `[배치/이름/진영 열]`을 같은 메시지에 포함해 적군을 즉시 배치할 수 있다.
- 봇이 준비 게시물을 올리면 `[아군/N열]` 형식으로 포지션을 선언한다.
- `[대련]`과 마찬가지로 라운드 상한에 도달하기 전에 한쪽이 전멸하면 그
  즉시 승자를 선언하고 종료된다.

```
[상시전투] @캐릭터A [배치/몬스터/적군 4열]
```

#### `캐릭터이름 [커맨드]` (프록시)

특정 캐릭터 대신 커맨드를 실행한다. 마스토돈 계정이 없는 적군 캐릭터 조작에 사용한다.
**본 전투뿐 아니라 대련/상시전투 진행 중에도 동일한 형식으로 사용할 수
있다** — 진행 중인 대련/상시전투가 있으면 그쪽이 우선 처리된다. 페이즈/턴
순서 제한(적군 행동 선언 단계, 선공/후공 순서 등)은 프록시로 실행해도
그대로 적용된다.

```
늑대 [이동/3 - 공격/전사]
```

#### `[전투발생]` — DM 전투

Admin이 **DM(다이렉트 메시지)** 으로 멘션해 즉시 시작하는 전투. 본 전투와
동일한 풀스탯 규칙(4페이즈 라운드, 스킬/버프/아이템 전부 사용 가능)을 쓰지만,
참전 신청·`[전투 준비]`·`[전투 개시]` 단계 없이 멘션 즉시 전투가 시작된다.

```
[전투발생] @캐릭터A @캐릭터B [배치/몬스터/적군 4열]
```

- 멘션된 계정이 아군으로 무작위 분산 배치된다.
- `[배치/이름/진영 열]`을 같은 메시지에 포함해 적을 즉시 배치할 수 있다.
- **여러 DM 전투를 동시에 진행할 수 있다** (본 전투는 세션이 1개뿐).
- 공개 필드 시트(이미지)는 쓰지 않는다 — 대신 매 답글에 현재 필드 상태를
  텍스트로 함께 붙여 보낸다.
- 봇의 응답 가시성(visibility)은 이 최초 멘션의 가시성으로 전투 내내 고정된다.

**진행 방식(모두 DM 스레드의 가장 최근 봇 게시물에 답글로):**

| 커맨드                    | 동작                                                  |
|-------------------------|-----------------------------------------------------|
| `[진행]`                  | 다음 페이즈로 진행 (본 전투의 `[진행]`과 동일한 페이즈 규칙)              |
| `[전투속행]`                | 라운드 종료 대기 상태에서 다음 라운드 시작                            |
| `[전투종료]`                | 전투를 강제 종료 (전멸 시에는 자동으로 종료되므로 이건 안전장치)              |
| `캐릭터이름 [커맨드]` (프록시)     | 계정 없는 캐릭터 대신 커맨드 실행                                 |
| (캐릭터 계정이 직접) `[커맨드]`    | 본 전투와 동일한 이동/공격/스킬/아이템 커맨드                          |

한쪽 진영의 HP 합계가 0 이하가 되면(전멸) 자동으로 전투가 종료되고 승자가 발표된다.

**중요:** 이 커맨드들이 인식되려면 반드시 **그 DM 전투의 가장 최근 봇 게시물**에
답글을 달아야 한다 — 페이즈가 넘어갈 때마다 "현재 유효한 게시물"이 바뀌므로,
스레드 중간의 오래된 게시물에 답글을 달면 인식되지 않는다.

### 캐릭터 시작 명령어

Admin이 아니라 `char_dict`에 등록된 캐릭터 계정이 직접 멘션해 시작하는
명령어.

#### `[대련]`

멘션한 본인과, 함께 멘션된 캐릭터들 간의 1:1 대련을 준비한다 — 대련은
(상시전투와 달리) Admin 명령어가 아니라 캐릭터 전용 명령어다.

- 멘션한 캐릭터 본인과 함께 멘션된 계정들이 참여 대상이 된다.
- 봇이 준비 게시물을 올리면 `[1팀/N열]` 또는 `[2팀/N열]` 형식으로 포지션을 선언한다.
- 모든 참여자가 포지션을 선언하면 대련이 자동으로 시작된다.
- 라운드 상한: `max(3, 참여자 수 + 1)`
- **한쪽 팀의 체력 합계가 0이 되면 그 즉시 승자를 선언하고 종료된다**
  (라운드 상한과 무관). 양쪽 다 체력이 남은 채로 라운드 상한에 도달하면
  체력 합계가 더 높은 쪽이 승리하고, 동점이면 승자 없음으로 종료된다.
- 이미 진행 중인 대련/상시전투가 있으면 새로 시작할 수 없다.

```
[대련] @캐릭터B
```

### 캐릭터 명령어 (전투 중)

**적용 조건:** 전투가 진행 중이고, 해당 캐릭터의 페이즈인 경우에만 처리된다.

- 아군: `아군 행동` 페이즈의 게시물에 답글
- 적군: `적군 행동 선언` 페이즈의 게시물에 답글
- DM 전투 참가자: 해당 DM 전투 스레드의 가장 최근 봇 게시물에 답글. 페이즈
  제한(아군은 아군 행동, 적군은 적군 행동 선언 단계에만)은 본 전투와 동일하게
  적용된다 — 위 [`[전투발생]` — DM 전투](#전투발생--dm-전투) 참고

커맨드 형식은 [커맨드 입력](#커맨드-입력) 섹션과 동일하다.

### 비전투 명령어

`char_dict`에 등록된 모든 캐릭터가 사용할 수 있다. 전투 맥락과 무관하게 언제든 사용 가능하다.

#### `[판정/스탯]`

1d6을 굴려 해당 스탯값을 더한 결과를 출력한다.

```
@system [판정/마법]
@system [판정/기술]
```

사용 가능한 스탯: `육체` · `지식` · `인간` · `마법` · `기술`

출력 예시:

```
◊ 판정: 3[마법] + 4[1d6] → 「7」
```

#### `[의뢰]` — 일일 의뢰

의뢰를 받는다. 1일 1회 제한. 일반 의뢰(상시조사) 시스템과 무관하게 항상 사용할 수 있다.

```
캐릭터: @system [의뢰]
  └→ 봇: {client_category} {client_name} {quest_content} 의뢰를 맡겼다. 어떻게 할까?
        (예: 길 잃은 어린아이로부터 부모를 찾아 달라는 의뢰를 맡겼다. 어떻게 할까?)
        (client_name에 조사까지 포함되어 있어야 함 — 봇은 조사를 붙이지 않는다)
        (스프레드시트 '일일 의뢰' 시트의 세 값 풀에서 각각 랜덤 선택해 조립)

캐릭터: @봇답글 [판정/스탯]
  └→ 봇: ◊ 판정: {값}[{스탯}] + {주사위}[1d6] → 「합계」
        {success_type}! (성공 유형별 메시지)

        의뢰를 완수했다. 사례로 1G를 획득했다. (소지금: {gold}G)
```

판정 합계에 따른 성공 유형:

| 합계  | 성공 유형    |
|-----|----------|
| ≥ 7 | 대성공      |
| 5–6 | 성공       |
| ≤ 4 | 아슬아슬한 성공 |

- 결과와 관계없이 항상 **1G 획득**된다.
- `(소지금: {gold}G)`는 1G를 획득한 뒤의 총 보유 골드다.
- 골드와 날짜가 스프레드시트 캐릭터 시트에 자동 업데이트된다.

#### `[상시조사]`

'일반 의뢰' 시트에 `active = TRUE`인 장소 행이 있을 때만 사용 가능하다.

```
캐릭터: @system [상시조사]
  └→ 봇: {활성 장소의 description} + 3개 수주처 선택지 + 자율 탐사

캐릭터: @봇답글 [장소명]
  ├→ (의뢰 존재) 봇: "[{장소명}](으)로 이동했다." + 의뢰 개요 카드 + "[수락] 입력" 안내
  └→ (자율 탐사 선택) 봇: "자유롭게 돌아다닐 수 있습니다."

캐릭터: @봇답글 (의뢰에 참여할 인원 전원 멘션) [수락]
  ├→ (성공) 봇: "@a @b @c 수락 확인. 「의뢰명」 의뢰를 수주했습니다."
  │     → '일반 의뢰' 시트의 해당 의뢰 행 `taken_by`에 참여자 acct를 쉼표로 기록
  ├→ (이미 수주된 의뢰) 봇: "@a @b @c 이미 다른 인원이 수주한 의뢰입니다."
  └→ (참여자 중 다른 의뢰를 이미 수주한 캐릭터가 있음) 봇: "@a @b @c 이미 다른 의뢰를
        수주한 캐릭터가 있어 수락할 수 없습니다: @이름"
```

`[수락]`은 의뢰 개요 게시물에 대한 답글이어야 하며, 발신자 자신과 함께
멘션된 캐릭터 전원이 한 번에 참여자로 등록된다(개별적으로 따로 `[수락]`을
답글할 필요 없음). 봇 응답은 대련/DM 전투와 마찬가지로 **참여자 전원을
게시물 맨 앞에 멘션**해 보낸다(성공/실패 응답 모두 동일).

- 같은 장소의 의뢰 3개(운반/탐사/전투)는 서로 다른 인원이 각각 독립적으로
  수주할 수 있다.
- 다만 한 캐릭터가 그 장소의 의뢰 하나를 이미 수주했다면(`taken_by`에 이름이
  있으면) 같은 장소의 다른 의뢰를 또 수주할 수 없다.
- 어느 의뢰가 수주됐는지는 `taken_by`에 영속적으로 기록되므로 봇이 재시작돼도
  유지된다. 의뢰가 끝나면 GM이 시트에서 `taken_by`를 직접 비워 다시 수주
  가능하게 만든다.

#### `[아이템명(/대상)(/개수)]`

비전투 상황에서 즉시 아이템 효과를 적용한다. 전투 중과 동일하게 "사용/"
같은 접두어 없이 아이템명으로 바로 시작하며, 첫 토큰이 실제 등록된
아이템명과 일치할 때만 인식한다(아이템명이 다른 커맨드 키워드와 겹치지
않는다는 전제). 대상과 개수는 순서 무관하게 인식하며(개수는 숫자 또는
`N개` 형태), 둘 다 생략 가능하다. 아이템 시트의 `item_type`이 `소모품`
또는 `비전투 소모품`인 아이템만 사용할 수 있다(그 외는 "◊ 사용할 수 없는
아이템입니다."로 거절).

```
@system [포션]           ← 자신에게 사용, 1개
@system [포션/2개]        ← 자신에게 사용, 2개
@system [포션/동료B]      ← 동료B에게 사용, 1개
@system [포션/동료B/2개]  ← 동료B에게 사용, 2개
```

- 등록된 아이템명 목록은 최대 5분(`get_cached_item_names`의 TTL)까지 캐싱된
  값을 쓴다 — 아이템을 새로 등록한 직후에는 최대 5분 정도 인식이 늦을 수
  있다(브래킷이 있는 모든 멘션마다 아이템 시트를 새로 읽는 낭비를 피하기
  위함).

**`소모품`** (예: 포션류):

- **회복(Heal) 효과를 가진 아이템만** 사용 가능하며, 그중에서도 수치 산출
  방식이 **고정값** 또는 **최대 체력 %** 인 경우만 지원한다.
- 개수를 지정하면(`[포션/2]`, `[포션/동료B/2]`) 그만큼 회복량과 소비량이
  비례해 늘어난다(고정값 20짜리 포션 2개 = 40 회복). 생략하면 1개.
- 보유 수량이 부족하면 거절되고, 성공 시 인벤토리가 즉시 차감되며 대상의
  `curr_hp`가 스프레드시트에 바로 반영된다.
- 회복량은 최대 체력을 넘지 않는다.
- 코스트/사거리는 무시된다(전투 중 사용할 때만 아이템 시트의 값을 그대로 쓴다).
- 출력은 전투 중 결과 표시와 동일한 형식("▹ 대상 | ±값 → 현재/최대")을
  재사용한다 — 회복/피해 등 효과 종류별로 문구를 새로 짓지 않는다.
  ```
  ◊ 포션 2개를 사용했습니다.

  ▹ 동료B | +40 → 90/100
  ```

**`비전투 소모품`** (예: "수상한 물약"):

- `effect_0`이 비어 있으며, **자신을 대상으로만** 사용 가능하다(다른 대상을
  지정하면 "◊ 자신에게만 사용할 수 있는 아이템입니다."로 거절).
- 아이템별 전용 로직으로 처리된다 — 현재 구현된 것은 "수상한 물약" 하나뿐이며,
  전용 로직이 없는 다른 비전투 소모품은 실제로 노출될 일은 없어야 하지만
  (구현할 때 함께 등록하는 게 정상 절차) 만약을 대비해 "◊ 등록되지 않은
  아이템입니다."로 거절한다 — 미구현도 플레이어 입장에서는 미등록과
  다를 바 없어야 하고, 어차피 처리 못 할 아이템을 소비 전에 걸러내기
  위함이다(인벤토리 소비 전에 확인한다).
- **"수상한 물약"**: 사용 시 "수상한 효과" 시트(`effect` 컬럼)에 등록된
  텍스트 중 하나를 무작위로 골라 `수상한 물약을 마셨다. ……어라? {효과}`
  형태로 답글을 낸다. 개수를 지정하면(`[수상한 물약/2]`) 그만큼(중복 허용)
  뽑아 `" 그리고…… "`로 이어붙인다. 뽑힌 텍스트 중 `체력이 {N} 회복된다.`
  형태가 있으면(여러 개면 합산해) 그 캐릭터의 `curr_hp`를 스프레드시트에도
  한 번만 반영하고, 첫 줄 뒤에 ` ({회복 후 체력}/{최대 체력})`을 덧붙인다.
  답글 마지막 줄에는 항상 "효과는 자정 혹은 스토리 진행 전까지 지속됩니다.
  기존에 진행 중이던 대화에는 반영되지 않습니다." 안내가 붙는다.
  ```
  수상한 물약을 마셨다. ……어라? 체력이 10 회복된다. 그리고…… 체력이 20 회복된다. (80/100)

  ◊ 효과는 자정 혹은 스토리 진행 전까지 지속됩니다. 기존에 진행 중이던 대화에는 반영되지 않습니다.
  ```

#### `[양도/아이템명/대상(/개수)]`

자신이 보유한 아이템을 다른 캐릭터에게 양도한다. 대상은 필수, 개수는
생략하면 1개.

```
@system [양도/포션/동료B]      ← 1개 양도
@system [양도/포션/동료B/3개]  ← 3개 양도
```

출력 예시:

```
◊ 양도 완료: 캐릭터A → 동료B에게 '포션' 3개 양도
```

- `item_type`과 무관하게 아무 아이템이나 양도할 수 있다
  (인벤토리 개수만 이동하며 효과를 사용하지는 않음).
- 보유 수량이 부족하면 거절된다.

#### `[가방]`

소지금과 보유 아이템 목록을 출력한다. 메시지 내 앞뒤 문구는 무관하며(다른
텍스트와 함께 있어도 `[가방]`만 인식), `[판정/스탯]`처럼 어떤 맥락에서도
사용 가능하다.

```
@system 확인 좀 할게 [가방]
```

출력 예시:

```
◊ 동료B의 소지품

▹ 소지금: 12G
▹ 포션×2: (자신 · 코스트 0 · 사거리 0) 체력을 20 회복한다. 비전투 상황에서도 사용 가능.
▹ 폭탄×1: (코스트 1 · 사거리 2) 대상에게 30의 피해를 입힌다.
▹ 수상한 물약×1: 마셔 봐야 아는 물약.
▹ 행운의 부적×1: 부적. 지니고 있으면 운이 좋아진다.
```

- `item_type`이 `기타`/`비전투 소모품`/`부적`이면 코스트/사거리는 항상
  0이므로 생략한다. 그 외(`소모품`/`전투 소모품`)는 아이템 시트의
  `cost`/`range` 값을 `(코스트 N · 사거리 M)`로 보여준다.
- `item_type`이 `소모품`이면 `target_rule`에 따른 대상 라벨이 코스트/사거리
  앞에 같은 괄호 안에 붙는다: `SkillTargetRuleSelf` → `자신`,
  `SkillTargetRuleNamed` → `개체/1`, `SkillTargetRuleNamedWithColumn` →
  `개체+열/1`, `SkillTargetRuleColumn`/`SkillTargetRuleAllyColumn` → `열/1`.
  (예: `(개체/1 · 코스트 1 · 사거리 1)`)
- `item_type`이 `소모품`이면 설명 뒤에 "비전투 상황에서도 사용 가능."이
  붙는다. `비전투 소모품`은 설명 자체로 비전투 전용임이 자명하므로 문구를
  붙이지 않는다. `부적`은 뒤가 아니라 설명 **앞**에 "부적. "이 붙는다.
  `전투 소모품`/`기타`는 아무 문구도 붙지 않는다.
- 인벤토리에는 있지만 아이템 시트에서 찾을 수 없는 항목(삭제된 아이템
  등)은 코스트/사거리 없이 "(아이템 정보를 찾을 수 없습니다)"로 표시된다.

- 개수가 0인 아이템은 목록에서 제외된다.
- 아이템이 하나도 없으면 소지금 줄만 출력된다.

### 디스패치 흐름

봇이 멘션을 받으면 아래 순서로 처리 경로를 결정한다.

```
멘션 수신
│
├─  1. 발신자가 Admin 계정? 또는 봇 자신의 [상시전투] 멘션?
│       └→ Admin 커맨드 처리 (전투 관리)
│         ├─ 진행 중인 DM 전투 스레드의 최신 게시물에 대한 답글이면
│         │   [진행]/[전투속행]/[전투종료]/프록시를 DM 전투용으로 처리
│         └─ 그 외엔 일반/상시전투/DM 전투 개시([전투발생]) 커맨드로 처리
│
├─ 1.5. 등록된 캐릭터 계정의 [대련] 멘션?
│       └→ 발신자 본인 + 함께 멘션된 계정을 참여 대상으로 대련 준비
│           (Admin 커맨드가 아니라 캐릭터 전용 커맨드)
│
├─  2. 대련/상시전투 준비 게시물에 대한 답글?
│       ├─ 상시전투: [아군/N열] 포지션 선언 처리
│       └─ 대련: [N팀/N열] 포지션 선언 처리 → 모두 선언 시 자동 시작
│
├─  3. 대련/상시전투 진행 중 커맨드 (active 게시물에 대한 답글)?
│       └→ 대련/상시전투 캐릭터 커맨드 처리
│
├─  4. [전투 준비] 게시물에 대한 답글?
│       └→ 참전 신청 목록에 추가
│
├─  5. 현재 페이즈 게시물에 대한 답글? (전투 중)
│       └→ 캐릭터 커맨드 처리 (이동/공격/스킬/아이템)
│
├─ 5.5. 진행 중인 DM 전투 스레드의 최신 게시물에 대한 답글?
│       └→ DM 전투 캐릭터 커맨드 처리 (페이즈 제한은 본 전투와 동일)
│
├─  6. 봇의 [의뢰] 안내 게시물에 대한 답글? + [판정/스탯] 포함?
│       └→ 일일 의뢰 판정 처리
│
├─  7. 봇의 [상시조사] 메뉴 게시물에 대한 답글?
│       └→ 장소 선택 처리 → 의뢰 개요 또는 탐사 안내 반환
│
├─  8. 봇의 의뢰 개요 게시물에 대한 답글? + [수락] 포함?
│       └→ 의뢰 수락 처리
│
├─  9. [판정/스탯] 포함?
│       └→ 독립 판정 처리 (롤플레이용)
│
├─ 10. [의뢰] 포함?
│       └→ 일일 의뢰 시작
│
├─ 11. [상시조사] 포함?
│       └→ 상시조사 메뉴 제공 (일반 의뢰 시트에서 실시간 조회)
│
├─ 12. [아이템명(...)] 포함? (첫 토큰이 등록된 아이템명과 일치)
│       └→ 비전투 아이템 사용 처리
│
├─ 13. [양도/아이템/대상(...)] 포함?
│       └→ 비전투 아이템 양도 처리
│
└─ 14. [가방] 포함?
        └→ 소지금/아이템 목록 조회
```

답글 맥락(어느 게시물에 달렸는지) 판단이 독립 키워드 판단보다 항상 먼저다.
